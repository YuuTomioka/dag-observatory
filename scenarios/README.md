# Scenarios

このディレクトリは、日本語で運用する代表フローと検証導線の入口です。

## 役割

- 利用者や運用者がどの流れで確認すべきかを示す
- 代表的な検証フローを再利用可能な形で残す
- 技術的な正本を再定義せず、実行と確認の導線を提供する

## 命名方針

- シナリオ名は対象フローが分かる形にする
- `representative-scenario.md`, `run-inspection-backtest-integrated-scenario.md` のように、流れや目的をそのまま名前に含める
- acceptance 用の具体的なシナリオを追加する場合は `acceptance/` 配下に置き、対象フローごとに分ける
- `test.md` や `flow.md` のような単独の汎用名は避ける

## フォーマット方針

- 最初に目的と前提条件を書く
- 手順、期待結果、観測確認点を分けて書く
- 利用者や運用者が追える日本語で書く
- 構造や仕様の正本は `blueprint/`、`implementations/`、`platform/`、`data/` を参照し、ここで再定義しない

## ライフサイクル方針

- 代表性があり反復して使う検証導線だけをここへ置く
- 一時的な確認メモや未整理の実験ログは `governance/tasks/` に置く
- フローが安定しないうちは placeholder を増やさず、具体的な実行導線が固まってから追加する
